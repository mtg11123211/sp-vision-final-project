# 伏击模式 V3 干跑判据（10-24 上午，30 min，一发不打）

> 前提：V2 编译通过（`Building CXX object ... task_2.cpp.o` + `Linking CXX executable task_2`）。
> **未过 V3 不打一发**（方案 §5 红线）。

命令：

```bash
cd ~/fp_aim
DSH_AMBUSH=1 DSH_FIRE_KEY_ENABLE=0 DSH_FIRE_DELAY=0.080 ~/run_measure.sh spin V3 0.0
```

（转靶 4 rad/s；lead 传 0.0 —— 伏击下 lead 结构性失效，传什么都一样，传 0 便于看出来。）

## 判据

| # | 判据 | 数值 | 出处 |
|---|---|---|---|
| 1 | cmd yaw 波动（`[dbg] arrive=` 连续 20 行） | 标准差 **< 0.1°**（静态钉住） | `[dbg] arrive` 行的 `cmd yaw=` |
| 2 | errY | **< 0.3°**（追踪模式 p50 1.30°） | summary A2 / `[dbg] arrive` |
| 3 | 触发节拍（`[dbg] ambush` 行） | ≈ **1.27 Hz** @4 rad/s（0.79 s 一行） | `grep -c 'ambush '` / 运行秒数 |
| 4 | `dt_align` 倒计时 | 单调递减 → 0 → 跳回 ~0.79 s，循环 | `[dbg] ambush` 行的 `dt_align=` |
| 5 | w 读数 | 与追踪模式同场一致（±0.05） | summary C2 |
| 6 | **肉眼**：板转正时检测框压住画面中心 | 偏差 **< 半板宽**（67 mm@3.5 m ≈ 1.2°，画面上约 12 px） | 看画面 + `[dbg] ambush-aligned` |
| 7 | **err_px 连续 10 次转正的均值** | **< 0.02**（归一化坐标，2% 画面宽 ≈ 25 px @1280） | `[dbg] ambush-aligned id=… err_px_x=… err_px_y=…` |

判据 6/7 是**零位交叉验证**：板转正那帧，若云台真的钉在弧点上，检测框中心应当落在画面中心；
连续的 err_px 均值 < 0.02 就说明"弧点 + 云台静态指向"这条链路没有系统性偏置，
可以进 V4 实弹（先按落点方向微调 B3，再 A/B）。

## 设计取向（防止再加"等待逻辑"）

- **阶段 1 不加任何「几何可信才下发」的门**：伏击点从"有 target"那一帧起就照常下发，
  挡火完全交给现有的 `stable` / `frames_since_init` / `arrive` / `interval` 门（代码零新增）。
- 新增的门控只有一处：相位门 `Δt_align ≤ B3 + t_flight`（它替代 facing 门，不是额外叠加）。
- `[dbg] ambush-aligned` 是**只读诊断**，不参与任何判断；`DSH_AMBUSH=0` 时整段不执行。
