### 1.5 启动日志（三行，一行看懂默认行为）

```
[task2] 到位门控 = 开（yaw 0.80° / pitch 1.28°，连续 3 帧）｜看门狗 关｜板面正对 ±25°、摆出 35° 才重新上膛（一块板只打一发）｜发弹间隔 0.20 s
[task2] 低位靶规则 = warmup(暖机期只打低位，可信后放开)（DSH_LOW_PLATE="1"，高度容差 0.10 m，信任 4 s）｜人工开火门 = 关（模式 hold(按住)，按键后端 evdev:…）
[task2] 出弹延时补偿 = 0.000 s｜选板 = 当前(current)｜到位容限 = 0.80°（固定角度）｜静止靶判据 = 30 °/s 且连续 10 帧
[task2] 预测时域 = 链路 0.000s + 出弹 0.000s + 飞行 ~0.126s（3.15 m @25 m/s 估）
```

> **方案①（2026-10-21 已实施）**：`DSH_LEAD` = **总提前量**（链路 + 云台滞后 + 出弹延时），
> 是**唯一的功能旋钮**；`DSH_FIRE_DELAY` 只作**记录/拆分标注，不再单独累加** ⇒
> **"同一段延迟在两处各补一次"在结构上不可能**（原来 `lead=0.057 + fire_delay=0.057` 会补两遍、
> 过补 0.83°，还会让人误判成"符号反了"）。
> 启动日志会直接现形；`DSH_FIRE_DELAY` 非 0 而 `DSH_LEAD=0` 时还会打一条 ⚠ 警告
> （"出弹延时没有进入补偿，请并进 DSH_LEAD"）。
> （按清单 ★10 的意见，**没有**加阈值告警——合法组合 `lead=0.057 + fire_delay=0.15` 会误报。）

## 5. 环境变量总表（副本最终）

| 变量 | 默认 | 作用 |
|---|---|---|
| `DSH_LOW_PLATE` | `1`（warmup） | 0/off 不参与｜1/warmup 不可信时只打低位、可信后放开｜2/always 永远只打低位 |
| `DSH_LOW_PLATE_Z_TOL` | 0.10 m | 低位组的高度容差 |
| `DSH_LOW_PLATE_TRUST_S` | 4.0 s | 高度差稳定多久算收敛（warmup 放开高板） |
| `DSH_FIRE_KEY` | `hold` | hold / toggle / always / never |
| `DSH_FIRE_KEY_ENABLE` | **0**（task_2）、0（task_3） | 人工开火门总开关 |
| `DSH_FIRE_KEY_DEV` | 自动扫描 | 指定 evdev 设备 |
| `DSH_AIM_SELECT` | `current` | `arrival` = 在弹丸到达时刻选板 |
| `DSH_FIRE_DELAY` | 0 | **出弹延时的记录值**（方案①：不再单独累加） |
| `DSH_ARRIVE_MM` | 0 | 到位容限按线性毫米（0 = 固定角度） |
| `DSH_ARRIVE_DEG` / `_PITCH_DEG` / `_FRAMES` | 0.8 / 1.28 / 3 | 固定角度到位容限 |
| `DSH_ARRIVE_WATCHDOG_SHOTS` | 0 | 挡 N 发自动解除（0 = 永不） |
| `DSH_PLATE_FACING_DEG` / `DSH_PLATE_REARM_DEG` | 25° / 35° | 面朝窗口 / 重新上膛角 |
| `DSH_STATIC_RATE_DPS` | 30 °/s | 静止靶判据的角速度阈值（帧率无关） |
| `DSH_STATIC_FRAMES` | 10 | 静止靶判据的连续帧数（clamp ≥1） |
| `DSH_LEAD` | 0 | **总提前量**（链路+云台滞后+出弹延时），**唯一功能旋钮**——改它必须重启进程（static 只读一次） |
| `DSH_TEST_TAG` | `run` | 给这一场起名（出现在汇总标题里） |
| `DSH_SUMMARY_FILE` | 空 | 汇总另存的独立文件路径（不依赖 tee 捕获） |

> **`DSH_LEAD` / `DSH_FIRE_DELAY` 是 `static` 一次性读取的**，改环境变量必须重启进程（清单 ★9）。
> `DSH_LEAD` 现在还被 `t_arrive` 吃了 ⇒ "改了没生效"的影响面变大，更要注意重启。
