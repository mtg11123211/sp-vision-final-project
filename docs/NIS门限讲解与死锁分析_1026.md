> 日期：2026-10-26　适用：`fp_aim_fkey`（task_3 前哨站）
> 性质：**复盘文档**。文中所有结论都可用「文件:行号」现场复核；未经验证的部分单独标注。
> 结论先行：本项目真正的坑不是「NIS 阈值取错了」，而是**两套阈值语义不一致 + 拒收时连 P 一起回滚 + 拒收后把失败标记抹掉**，

## 1. NIS 的定义与几何意义

### 1.1 从残差到马氏距离

卡尔曼更新时，先算**新息**（innovation，也叫残差）：

```
r = z − h(x̂⁻)          // 观测 − 预测观测
```

再算新息协方差：

```
S = H P⁻ Hᵀ + R        // P⁻：先验状态协方差；H：观测雅可比；R：观测噪声协方差
```

NIS（Normalized Innovation Squared）：

```
NIS = rᵀ S⁻¹ r
```

**它不是「误差有多大」，而是「误差是几倍标准差」的平方**。因为 `S` 已经把两件事算进去了：
① 滤波器自己有多不确定（`P`）；② 传感器有多吵（`R`）。

同一份 0.1 m 的高度误差：
- 距离 3 m、`P_z` 很大（刚初始化）⇒ NIS 很小，滤波器认为「正常，可能是我自己不确定」；
- 距离 3 m、`P_z` 很小（已收敛）⇒ NIS 很大，滤波器认为「我很有把握，这观测不对劲」。

### 1.2 为什么自由度是 4

NIS 的分布只取决于**观测向量的维数**，与状态维数无关。
本项目观测向量（`target.cpp:300`）：

```cpp
Eigen::VectorXd z{{ypd[0], ypd[1], ypd[2], ypr[0]}};
//                  yaw     pitch   距离    板朝向
```

⇒ 4 维 ⇒ 模型正确时 **NIS ~ χ²(4)**，均值 = 4。

> 常见误解：「NIS 应该接近 0 才健康」。错——健康帧的 NIS 在 4 附近波动，
> 90% 的正常帧 NIS 落在 0.71–7.78 之间。把阈值设成 1.5（历史上真发生过，见
> `extended_kalman_filter.hpp` 注释）会把绝大多数正常帧判成失败。

### 1.3 χ²(4) 分位表（选阈值用）

| 分位 | NIS | 用途 |
|---|---|---|
| 50% | 3.36 | 中位数 |
| 90% | 7.78 | — |
| **95%** | **9.488** | 本项目**统计失败率**用的阈值（`ekf_.nis_threshold`）|
| 99% | 13.28 | — |
| **99.7%** | **≈16.25（代码取 16.27）** | 本项目**硬拒收**用的阈值（`nis_reject_threshold`）|
| 99.9% | 18.47 | — |

复现：

```python
from scipy.stats import chi2
for p in (0.90, 0.95, 0.99, 0.997, 0.999):
    print(p, round(chi2.ppf(p, df=4), 3))
```

## 2. 本项目里的两套阈值（最容易讲错的地方）

| 阈值 | 值 | 定义位置 | 作用 | 触发后果 |
|---|---|---|---|---|
| `nis_threshold` | 9.488（95%）| `tools/extended_kalman_filter.hpp` | 每帧判断是否往 `recent_nis_failures` 里压 1 | 只影响**失败率统计** |
| `nis_reject_threshold` | 16.27（99.7%）| `sentry.yaml:66` → `task_3.cpp:61` | `update_checked` 判断是否回滚这一帧 | 影响**状态是否更新** |

```cpp
// task_3.cpp:61
const double nis_reject_threshold = tools::read_or<double>(yaml, "nis_reject_threshold", 16.27);
```

### 2.1 「接受但记失败」带（本项目故障的主战场）

```
NIS < 9.488                → 正常：更新状态，记 0
9.488 ≤ NIS ≤ 16.27        → 接受但记失败：状态照常更新，失败率 +1，日志无拒收记录
NIS > 16.27                → 硬拒收：回滚 x、P，并把刚记的失败 pop 掉
```

**中间这条带是隐形的**：观测被采信（状态被拉偏），但失败率照样上涨；
而失败率一旦超过 0.3（`max_nis_failure_rate`），`stable=false`，**不开火**。

```cpp
// task_3.cpp:381-383
const bool stable =
  relax_lv2 || (target.is_converged() && frames_since_init >= min_frames_for_fire &&
                nis_failure_rate < max_nis_failure_rate);
```

注意：`DSH_FIRE_RELAX=1` 只放开 `observed_ok` 和 `holding`，**`stable` 是无条件要求的**
（`task_3.cpp:400-405` 的 `fire = observed_ok && stable && ...`）⇒ **relax 不能绕过 NIS 门**。

### 2.2 拒收路径的完整时序（target.cpp:306-333）

```cpp
309:  const Eigen::VectorXd x_before = ekf_.x;      // ① 备份
310:  const Eigen::MatrixXd P_before = ekf_.P;
311:  update(armor);                                 // ② 正常更新（会 push 失败标记、改 x/P）
319:  if (ekf_.last_nis > nis_reject_threshold) {
320:    ekf_.x = x_before;                           // ③ 回滚状态
321:    ekf_.P = P_before;                           //    连协方差一起回滚 ← 关键缺陷
326:    auto & recent = ekf_.recent_nis_failures;
327:    if (!recent.empty()) {
328:      recent.pop_back();                         // ④ 把失败标记退掉 ← 可观测性缺陷
329:      ...
332:      ekf_.data["nis_fail"] = 0.0;
```

四个后果，逐条对应：

1. **`P` 不增长** ⇒ 滤波器对「我可能错了」永远不认账 ⇒ 下一帧的 `S` 不变小 ⇒ NIS 不会因为拒收而下降 ⇒ 自锁。
2. **失败标记被 pop** ⇒ 连续拒收在系统里**没有任何计数器** ⇒ HUD 的 `nis_failure_rate` 显示 0，看起来「很健康」。
3. **状态被回滚** ⇒ 错误的先验被永久保留；而这一帧的观测（本来能纠正它）被丢弃。
4. **拒收不阻止开火**：`has_detection` 仍为真，`stable` 里的失败率刚被 pop 回低位 ⇒ 系统继续用**过期状态**瞄准和开火。

## 3. 定量：多大的高度误差会触发哪一档

### 3.1 参数（3.2 m 处，前哨站）

| 量 | 值 | 来源 |
|---|---|---|
| `r_cam_yaw` / `r_cam_pitch` | 5e-4 rad²（σ ≈ 1.28°）| target.cpp（`kRCamYaw/kRCamPitch`）|
| `r_distance` | ≈ 0.072 m²（σ ≈ 0.27 m）| `(1e-2 + 5e-3 d²)(ln|Δang|+1)`，d=3.2、Δang≈0.2 |
| `r_armor_yaw` | ≈ 0.215 rad²（σ ≈ 26.6°）| `0.05 + 0.01 d² + 0.2/d` |
| `P_z`（收敛后）| ≈ 0.005 m² | 由 P0=1 经单帧更新后估算，实际随历史变化 |
| 灵敏度 | ∂pitch/∂z ≈ 1/d = 0.3125 rad/m | 小角度近似 |

⇒ `S_pitch ≈ H²P_z + R ≈ 9.9e-4 rad²`（σ ≈ 1.8°）
⇒ `NIS ≈ Δz² / (d²·S_pitch) = Δz² / 0.0101`

### 3.2 表格（仅 pitch 一项，其余三项只会让 NIS 更大）

| Δz（m）| 角度误差 | NIS（≈）| 落在哪一档 | 现场含义 |
|---|---|---|---|---|
| 0.05 | 0.90° | 0.25 | 正常 | — |
| 0.10 | 1.79° | 1.0 | 正常 | 板半宽量级，仍可打中 |
| 0.20 | 3.58° | 4.0 | 正常（≈均值）| 边缘擦板 |
| **0.26** | **4.65°** | **6.7** | **正常** | 现场 dh 误差下限 |
| **0.31** | **5.55°** | **9.5** | **开始记失败** | — |
| **0.35** | **6.26°** | **12.1** | **接受但记失败** | 现场 dh 误差上限 ⇒ 失败率上涨 ⇒ 不开火 |
| **0.41** | **7.34°** | **16.6** | **硬拒收** | 状态回滚 |
| 0.50 | 8.95° | 24.7 | 硬拒收 | — |

**这张表是整份文档的核心**：它解释了为什么现场表现为
「有时能连发、有时一板只打两发」——误差在 0.26–0.35 m 之间来回，
正好在「正常 / 记失败 / 拒收」三条线附近摆动。

### 3.3 为什么「一次坏帧锁死一整场」不成立

刚初始化时 `P_z = 1 m²`（`P0_dig_outpost`），此时 `S_pitch ≈ 0.098 rad²`：

| Δz（首帧）| NIS（P=1 时）| 结果 |
|---|---|---|
| 0.5 m | 2.5 | **接受**，状态被拉回一半 |
| 1.0 m | 10.0 | 接受但记失败 |
| 1.26 m | 16.6 | 才开始拒收 |

⇒ **单帧坏初值（0.5 m 量级）会被大 `P` 吸收，不会锁死。**
真正的自锁需要「模型持续失配」（关联错板、相位滞后超过容差、dh 错到 0.4 m 以上），
而不是「一次坏帧」。这一点与网上常见的简化说法不同，面试时要说准。

## 4. Bug 分析（分三级：已证实 / 定量 / 待证实）

### 4.1 已证实的设计缺陷（代码可指）

| # | 缺陷 | 位置 | 后果 |
|---|---|---|---|
| B1 | 拒收时 `P` 一起回滚 | target.cpp:321 | 不确定性永不增长，无自愈路径 |

| B4 | 两套阈值语义不一致（9.488 vs 16.27）| hpp / sentry.yaml:66 | 「接受但记失败」带隐形存在，不开火却无拒收日志 |

| B6 | NEES 用后验 `P` 计算 | extended_kalman_filter.cpp | 仅诊断量，未参与门控；数值偏小（不影响功能）|

### 4.2 与前哨站 id 错位的耦合（本项目的真实触发源）

- 前哨站三块板外观相同，`id` 是「相对首帧的槽位」（target.cpp:82 用 `ypr[0]` 锚定），
  重启后首帧相位不同 ⇒ 槽位与物理板的对应关系**每次重启都可能换**。
- 层高按槽位分配（target.cpp:419-420），而 `dh` 在 `update_ypda` 里被冻结（:265-266）
  ⇒ 滤波器永远学不回来。
- 槽位错一位 ⇒ 高度误差 0.26–0.35 m ⇒ 正好落在 §3.2 的敏感带
  ⇒ 表现为「随启动相位变化的命中率抽奖」。
- 最终版的逐层 `dz` 补偿（`DSH_DZ0/1/2`，task_3.cpp:306-319）**也是按 `aim_id` 绑定的**，
  所以补偿跟着槽位一起漂——这是已知残留缺陷，不是修复。

## 5. 修复方案（2026-10-27 已实施 P1/P2/P3，见 §9；P4/P5 仍未做）

| 优先级 | 改动 | 说明 | 验证 |
|---|---|---|---|
| P1 | 连续拒收计数 → `needs_reinit` | 拒收自增、接受清零；> 20 帧（≈0.35 s）返回 `needs_reinit`，task_3 丢目标、用当前帧重建。**这是现场唯一能自愈的机制** | 注入坏初值/遮挡首帧，看是否 20 帧内重锚 |
| P2 | 拒收时只回滚 `x`，`P` 放大 10 倍 | 给滤波器留一条「我可能错了」的出口 | 人为制造 0.4 m 偏差，看能否在数帧内爬回来 |
| P3 | 初始化合理性检查 | `center_z ∈ [0.8, 1.6] m`；`ypr` 与距离一致性；不满足直接拒绝建目标 | 坏帧注入测试 |
| P4 | 失败率与开火门解耦 | 失败率只作「健康度」显示；开火门改用「连续拒收帧数」这一更直接的指标 | 统计修复前后不开火时长 |
| P5 | 统一两套阈值语义 | 要么都用 16.27，要么在注释里写清「统计 95% / 拒收 99.7%」 | 代码评审 |
| P6 | 按实测 z 重锚 id（治本） | 收敛后按三块板的实测 z 排序，一次性把槽位与物理板对齐；或维护「物理板—高度」表 | 重启 10 次，检查 id→高度一致性 |

> 注：P1–P4 都不改变已有参数，`DSH_DZ*` / `DSH_OUTPOST_DH` 可继续使用。

## 6. 面试速查（NIS 相关 8 问）

**Q1：NIS 是什么？为什么不用残差绝对值？**
> 新息按新息协方差归一化后的平方和，`rᵀS⁻¹r`。残差有量纲（rad/m/rad），且不同距离、不同板朝向下噪声水平不同；NIS 把「误差是几倍标准差」统一成一个无量纲标量，可以直接和卡方分布比。

**Q2：为什么自由度是 4？正常值是多少？**
> 观测向量 4 维（yaw、pitch、距离、板朝向），与状态维数 11 无关。模型正确时 NIS ~ χ²(4)，均值 4，95% 分位 9.488。

**Q3：你们的阈值是多少？为什么有两个？**
> 统计失败率用 9.488（95%，灵敏），硬拒收用 16.27（99.7%，保守）。这是设计选择，但**副作用是中间带「接受但记失败」**——状态照常更新、失败率照样涨、日志里没有拒收记录。这个带是我们故障的主战场。

**Q4：那「不开火」到底是怎么发生的？**
> 层高误差 0.26–0.35 m ⇒ NIS 6.7–12.1 ⇒ 部分帧落进「接受但记失败」带 ⇒ `recent_nis_failures` 在 100 帧滑窗内超过 0.3 ⇒ `stable=false` ⇒ 不开火。而 `DSH_FIRE_RELAX=1` 绕不过 `stable`（task_3.cpp:381-383）。

**Q5：为什么说滤波器会自锁？**
> 拒收时 `x` 和 `P` 一起回滚（target.cpp:319-321）。`P` 是「我有多不确定」，拒收本应让它变大；一起回滚等于拒绝承认自己可能错，下一帧 `S` 不变小，NIS 不会降，形成正反馈。

**Q6：为什么日志里看不出问题？**
> 拒收后把刚记的失败标记 `pop_back()` 掉（target.cpp:326-328），连续拒收零计数，HUD 失败率恒 0。原意是防止 `stable` 永远为假，副作用是把唯一的故障信号也抹掉了。

**Q7：一次坏帧会不会锁死？**
> 不会。初始化时 `P_z=1 m²`，0.5 m 的初值误差只对应 NIS≈2.5，会被吸收。真正的自锁需要「模型持续失配」——关联错板、相位滞后超容差、或 dh 错到 0.4 m 以上。这一点要说准，别夸大成「一次坏帧锁死」。

**Q8：怎么修、怎么验证？**
> 连续拒收计数 → `needs_reinit`；拒收只回滚 `x`、放大 `P`；初始化做 z 范围检查；失败率与开火门解耦。验证：注入坏初值/遮挡首帧看能否 20 帧内重锚；统计连续拒收帧数分布；重启 10 次检查 id→高度一致性。

## 9. 修复实录（2026-10-27 已改码，待车机编译验证）

> 本节把 §5 里「设计级」的 P1/P2/P3 落到了代码上，外加一处 run 脚本勘误。
> 每一条都用大白话讲清楚「为什么原来会死、为什么这么改能活」。

### 9.1 修复一：连续拒收看门狗（F1+F2）—— 给死锁装一个「重启按钮」

**原来的问题，打个比方**：滤波器像个固执的学生，第一次听课记错了笔记（单帧 PnP 初值坏），
之后老师（每帧观测）讲的内容和他笔记对不上，他就把老师的每一次纠正都当“超纲内容”退回去
（NIS > 16.27 ⇒ 拒收）。更糟的是他还悄悄把“被退回”的记录从 attendance 上擦掉
（target.cpp 的 pop_back），所以从外面看（HUD 失败率 = 0）他“全勤且健康”，
实际上是把自己锁死在错误笔记里，直到下课（进程重启）都出不来。

**改了什么**：
- `target.hpp`：新增 `needs_reinit()` / `reject_streak()`，常量 `kRejectReinitFrames = 20`
  （约 0.35 秒 @58fps——0.35 秒内一帧都没被接受，就不是“偶发噪声”，而是系统性错位）。
- `target.cpp update_checked`：拒收时 `reject_streak_++`，接受时清零（target.cpp:342/:368）。
- `task_3.cpp`（:268-280）：`needs_reinit()` 为真 ⇒ 打 warn 日志 ⇒ **用当前帧重建滤波器**
  （`frames_since_init = -1` 抵消尾部 `++`，重新走预热帧）。

**为什么阈值取 20 帧**：58–67 fps 下 20 帧 ≈ 0.30–0.35 秒。真·瞬时遮挡（1–5 帧）不会触发；
而锁死是“帧帧拒收”，0.35 秒内必然到 20。取太短会把正常换板/NIS 波动误判成锁死（乱重建），
取太长现场等待时间不可接受。**20 是“错过 1/3 秒就当卡死”的工程折中。**

### 9.2 修复二：拒收时 P 不再原样回滚（F3）—— 让滤波器学会「承认自己可能错了」

**原来的问题**：拒收时把状态 x 和协方差 P **一起**回滚（target.cpp 旧 :320-321）。
P 的含义是“我对当前状态有多不确定”。拒收 = 观测和预测严重不符 = 明明该更不确定了，
结果把 P 也还原回去 ⇒ 滤波器永远自信 ⇒ 下一帧新息协方差 S 不变大 ⇒ NIS 不变小 ⇒
继续拒收 ⇒ 死循环。这就是 §4.1-B1 说的自锁根因。

**改了什么**（target.cpp:344-350）：x 照旧回滚（脏观测不采信），但 P 改为
`P_before × 10`（对角元超过 500 就不再放大，防爆炸）。

**为什么 ×10 能解锁**：S = H·P·Hᵀ + R。P 放大 10 倍 ⇒ S 跟着变大 ⇒ 同样的残差算出来
NIS 缩小约 10 倍 ⇒ 原来“超纲”的观测两三帧内就变回“可接受”⇒ 状态被正常拉回真值。
打个比方：原来学生死咬“我的笔记没错”，现在改成每被退回一次，就把“我对笔记的信心”打一折——
信心降到足够低，老师的纠正就能进笔记了。上限 500 是防止连续拒收时 P 指数爆炸
（P0 里 w 的方差本来就是 100，量级对得上）。

**代价（诚实说明）**：若观测真的是离群值（比如顶部第四块板漏进关联），膨胀后的滤波器会更
容易采信它一两帧。这道风险由两道既有防线兜住：z_window/top_margin 过滤 + 9.2 的看门狗
（真被带偏就整体重建）。实测要盯 `[Target] NIS ... rejected` 日志不能连续刷屏。

### 9.3 修复三：构造合理性门禁（F4）—— 把「一帧毒」挡在门外

**原来的问题**：滤波器初值全部来自**一帧** PnP（target.cpp:74 `center_z = xyz[2]`、:82 把
它直接当 x0[4]）。只要建目标那一刻的板恰好是斜的、半遮挡或 PnP 解飘了，初值就带 0.5 m 量级的
错——而前哨站几何列全程冻结（target.cpp:265-266）、层高 dh 是常数，**滤波器永远学不回来**。
一次坏帧 = 一场报废。

**改了什么**：构造函数里对前哨站加钳位（target.cpp:84-95）：
`center_z ∉ [0.8, 1.6] m` ⇒ `valid_ = false`（现场可用 `DSH_NO_ZCLAMP=1` 关闭这道门）。
主循环三处建目标的地方（task_3.cpp:258-263 首建、:272-281 看门狗重建、:292-300 发散重建）
都改为 **`fresh.valid()` 不过就不入役**，下一帧再试。

**为什么区间取 [0.8, 1.6]**：现场 HUD 实测 x[4]（= 初值 center_z）为 1.06–1.19 m（10-25 录像），
±0.4 m 的余量覆盖板凳高度差异；而录像里出问题的 0.642 正好落在界外——这道门能拦住它。
比喻：以前新生入学不做体检，一个病人能把全班传染；现在先量体温，不合格不让进教室，下节课（下一帧）再来。

### 9.4 附带勘误：run3.sh 启动配置硬编码错误（不算死锁，但同等级的雷）

**链路事实**：task_3 用哪份 yaml **不是编译期决定的**（`make -j2 task_3` 只管编译，
CMakeLists 里没有任何 yaml 引用），而是**运行期命令行第一个位置参数** `@config-path`
（task_3.cpp:30/37）。而现场一键脚本 `tools/onsite/run3.sh` 最后一行写的是：

```bash
exec "./build/$BIN" configs/standard.yaml     # run3.sh:65（旧）
```

——**用步兵配置启动前哨站程序**。这是照抄 run2.sh 时漏改的（run3.sh 头部注释自己写着
「和 run2.sh 的差别只有三处」，偏偏没算配置文件这一处）。后果正好是手册预警的坑③：
standard.yaml 的 `rotation_angle: 0`（步兵相机正装）套在哨兵（倒装，必须 180，sentry.yaml:9）
上 ⇒ 画面上下颠倒必空；且 `pitch_offset: 0.5`（task2 的标定，sentry.yaml 是 0.0）也会被
task_3.cpp:58 读进去 ⇒ 系统性打偏。更隐蔽的是 run3.sh:31 的存在性自检也只查 standard.yaml
——用错配置反而「检查通过」。

**改了什么**（run3.sh:16-22/:36/:69-70）：

```bash
CFG="${FP_AIM_CFG:-configs/sentry.yaml}"   # 缺省哨兵配置，FP_AIM_CFG 可覆盖
[ -f "$CFG" ] || { ...; exit 1; }
exec "./build/$BIN" "$CFG"
```

**为什么用环境变量而不是写死**：和全项目的 `DSH_*` 两层参数哲学一致——yaml/脚本给缺省，
环境变量做现场覆盖；万一哪天要在步兵车上验证 task_3 共享代码，`FP_AIM_CFG=configs/standard.yaml`
一行就能切，不用改脚本。
