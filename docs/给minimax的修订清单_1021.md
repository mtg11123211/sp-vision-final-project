## 修订 1：低位靶从二态开关升级为三态（off / warmup / always）

**问题**：`实现思路讲解.md` §1.1 的前提"x[10] 这一列在整个挡位里被冻结"**不成立**——
`target.cpp:227-229` 首次换板即置 `rlh_initialized_ = true`，之后几何列放开量测更新
（`target.cpp:250` 注释明写"车体换板后允许单板观测更新半径及高度差"）。
真实情况是弱化版：**x[10] 从 0 起步、先验紧（P0=0.001）、靠换板观测收敛；收敛之前高板 z 偏低**。
于是现有规则"永久只打低位"是把一个**瞬态问题**（收敛前的偏差）当成**永久问题**处理，
收敛后白白丢掉一半开火机会。

**修法**（回应"是否加开关"：现有 `DSH_LOW_PLATE` 的 0/1 保留，中间加一态）：

```
DSH_LOW_PLATE = 0 / 1 / 2
  0 (off)    完全不参与（现状语义）
  1 (warmup) 【新默认】x[10] 不可信时只打低位；可信后自动放开高板
  2 (always) 永远只打低位（保守模式，正式提交想兜底再用）
```

warmup 的"可信"判据（**不改框架，只用已有可观测量**）：
- 4 板模型里高板 z = x[4] + x[10]、低板 z = x[4]，所以 **dz（z_aim − z_min）就是 x[10]**；
- `dz > z_tol`（即 `active && aim_is_low==false` 的高板确实存在）**连续保持
  `DSH_LOW_PLATE_TRUST_S`（默认 4.0 s）**，且期间 EKF 未重建 → 判收敛，放开高板；
- 三个"三清"位置（`task_2.cpp:396-398 / 420-422 / 425-427`）把信任计时一并清零
  （换目标 / 滤波器重建 / 发散重建都意味着 x[10] 重新从 0 学起）；
- 平靶（四板同高）时 dz 永远 < tol → active=false → 规则自动失效，warmup 与现状一致（安全）；
- 状态翻转打一行日志：
  `[task2] 低位靶规则：dz={:.2f} m 稳定 {:.1f} s，x[10] 视为已收敛，放开高板`。

**位置**：`src/low_plate.hpp`（LowPlate 结构加 `trusted` 字段与计时入参）、
`src/task_2.cpp:173-174`（读三态 + TRUST_S）、`:537-541`（评估与放行）、三个三清处。
**同步改文档**：§1.1 前提改成上面的弱化版口径；§1.4 代价表补"warmup 模式下暖机约 4 s，
之后恢复 2.55 Hz"。

## 修订 2：静止靶判据——保留实现，改口径，参数化帧数

**先自我更正**：评审初稿说"真实代价是 0.17 s 识别延迟"——**过重了**。
`facing_still_frames` 攒满后 `target_static` 持续为真，延迟只在**每次静止开始后的第一发**生效，
且与 `min_frames_for_fire`（10 帧）的滤波暖机**并行**，实际几乎无感。
`实现思路讲解.md` §3.2 建议的"零位标定加 DSH_PLATE_REARM_DEG=0.01"可以删掉。

**修法**：
1. 代码保留 facing 差分判据（对 x[7] 瞬时噪声的鲁棒性是真的），把连续帧数参数化：
   `DSH_STATIC_FRAMES`（默认 10，现场可降 5–6）——`task_2.cpp:529` 一处；
2. 文档删掉"起步爬升 / w 反向过零误判被改善"的声称：0.5°/帧 @60fps ≈ 0.52 rad/s，
   与原 `|x[7]| < 0.5` 的边界几乎重合，该场景两者行为相同；
   改成"收益 = 不依赖 x[7] 的收敛过程与瞬时噪声"；
3. 判据数字表补一行 45 fps（开录像）下的换算：0.5°/帧 ≈ 0.39 rad/s，低速爬升段更宽。

## 修订 3：默认值对齐"还原原版行为"原则

**问题**：`实现思路讲解.md` §0 宣称"每层默认不改变原行为"，但 `DSH_LOW_PLATE=1`、
`DSH_FIRE_KEY_ENABLE=1`（task2）默认就是开的——自相矛盾。

**修法**（取"改默认值"而非"改原则声明"）：
- `DSH_FIRE_KEY_ENABLE`（task2）默认 **0**。理由：正式提交每任务仅一次，操作员忘按 F = 整场零发；
  调试期显式开，HUD 第二行已有 `F=` 状态可查。task_3 维持默认 0 不变；
- `DSH_LOW_PLATE` 默认 **1（warmup）**——warmup 语义下"默认开"不再矛盾：
  平靶自动失效 + 收敛后自动放开，趋近无害；想彻底关仍可设 0；
- 启动日志（`:195-203`）确保每个机制的开/关/模式一行打全，让"默认行为"上车即可审计。

## 修订 4：`t_arrive` 补上链路 57 ms（一行 + 声明前移）

**问题**：`task_2.cpp:468` 的 `t_arrive = 距离/弹速 + fire_delay_s` **漏了 `DSH_LEAD` 的 57 ms 链路延迟**。
到达朝向的评估时刻应为 t0 + 链路 + 出弹 + 飞行；现在少算一段，
到达朝向系统性低估 w×57ms（低挡 13°、中挡 29°）——修正前 §6 的"到达朝向 ≈ 0"判据本身不成立。

**修法**：
1. 把 `:562` 的 `static const double lead_s = ...` **声明挪到选板块之前**
   （建议放 `:179` `fire_delay_s` 读取旁；值不变，只为编译顺序）；
2. `:468` 改为：
   ```cpp
   const double t_arrive = dist_guess / std::max(1.0, v_guess) + fire_delay_s + lead_s;
   ```
3. 行为检查：`DSH_AIM_SELECT=current` 时 t_arrive 只进日志，无影响；`DSH_LEAD=0` 时退化为现状。

**验证**：开 `arrival` 后看 `fire-gate` 行 `plate=(现朝向→到达朝向)`，
w>0 时现朝向应为负、**修正后**到达朝向才真正趋 0。

## 修订 5：三段延时归属表 + 启动日志自证 + 双补保险丝

**问题**：链路 / 出弹 / 飞行三段延时分别由谁补没有文档；`DSH_LEAD` 与 `DSH_FIRE_DELAY`
对同一块板的补偿是**加性**的（视在角速度微调 vs 板相位前移，一阶等价），
"fire_delay 填 0.157 全包 + lead 仍开 0.057"会双重补偿 57 ms，文档无警告。

**修法**：
1. 文档加表：

   | 时段 | 谁补 | 参数 |
   |---|---|---|
   | 曝光→云台到位（链路） | `DSH_LEAD`（视在角速度微调） | 0.057 s |
   | 开火指令→出膛 | `DSH_FIRE_DELAY`（calc_aim 的 t_extra + 选板 t_arrive） | 现场量，先 0.1 |
   | 出膛→弹着 | calc_aim 内部 t_flight 迭代 | 自动 |

   一句话规则：**57 ms 只允许存在于 DSH_LEAD 一处**；若用 fire_delay 全包则必须 `DSH_LEAD=0`。
2. 启动日志加一行（放 `:199-203` 那组后面）：
   `[task2] 预测时域 = 链路 {:.3f}s + 出弹 {:.3f}s + 飞行 ~{:.3f}s（3.15 m @25 m/s 估）`
   ——双补会在这一行直接现形。
3. 可选保险丝：`lead_s > 0.04 && fire_delay_s > 0.13` 时打一行 warn"疑似 57 ms 补了两次"。

## 修订 6：task_3 摘除低位靶门（真雷）

**问题**：task_3 挂了低位靶门（`task_3.cpp:78-79, 300-302, 305`），默认 tol =
`outpost_z_window`(0.30)，前哨站 0.2 m 阶梯下 low_count=total → 恰好永不激活（防御性但多余）；
**但跑 task_3 时若沿用 task_2 的 `DSH_LOW_PLATE_Z_TOL=0.10`，会拦掉 +0.2 台阶那块板**——
12 Hz 拼血量（30 s 内 75 发命中）的任务被拦 = 直接掉血量分。

**修法（推荐：删）**：前哨站没有低位靶的适应症——三块中部板全是合法目标，顶部板已有
`outpost_z_window` / `outpost_top_margin` 两道过滤，阶梯高度是图纸定值且 EKF 全程冻结，
不存在 x[10] 收敛问题。删掉 `:14` include、`:78-84` 读取与日志、`:300-305` 评估与 low_ok。
若想保留结构一致性，至少改用 task3 专属变量名（`DSH_T3_LOW_PLATE`，默认 0），
并在 `run3.sh` 里 `unset DSH_LOW_PLATE DSH_LOW_PLATE_Z_TOL` 防串味——但少一个门少一个雷，删最稳。

## 修订 8：F 键 / 开火授权的窗口显示方案（三件套）

**现状的两个真 bug（先修）**：
1. **状态行画在 `has_target` 分支里**（`task_2.cpp:732-739`）——没目标时整行消失，
   而"目标丢了还在找 F 状态"恰恰是最需要它的时刻。F 段必须移到分支外、每帧画；
2. **`DSH_FIRE_KEY_ENABLE=0` 时显示误导**——Gate 与 enable 无关地构造，HUD 仍显示
   `F=松开`，操作员会以为开火被挡、去按一个不起作用的键。显示必须包含有效 enable 状态。

**方案（三件套，代码锚点已核）**：

### 8.1 大色块徽章（右上角 ≈200×48，远距离可见）

| 有效状态 | 徽章 |
|---|---|
| `fire_key_enabled == false` | 灰底白字 `开火门 关（自动开火）` |
| enabled 且 `!allowed()` | 红底白字 `SAFE 禁火` |
| enabled 且 `allowed()` | 绿底白字 `ARM 允许开火` |
| 后端读键异常 | 黄底黑字 `后端异常 (后端名)` |

- 实现位置：`task_2.cpp` 主循环 `hud.draw(...)`（:765）之后、`cv::imshow`（:767）之前，
  写成 task_2.cpp 内的 static 辅助函数（**不要**放进 fire_key.hpp——它保持零工程依赖，
  keytest 才能单独编译；fire_key.hpp 只需补 getter）；
- 绘制顺序在 hud.draw 之后，保证不被覆盖。

### 8.2 状态行（全量信息，F 段无条件画）

```
开火门=开(hold/evdev F=按下)   ← 无目标时也画这一段
低位靶=warmup(dz=0.07 信任中2.1/4.0s)  瞄准板=2 facing=-18°→+3°   ← has_target 分支内
```

- `Gate` 补三个公开 getter：`bool pressed()`（原始键态，hold 模式=allowed）、
  `bool latch()`（toggle 锁存）、`bool degraded()`（后端读键异常标志）；
  `mode_text()` / `backend_name()` 已有；
- toggle 模式的措辞用 `锁定/解锁`，不用 `按住/松开`（锁存和按键是两回事）；
- enable=0 时 F 段显示 `开火门=关(不用按F)`。

### 8.3 边沿日志（forensic，比 60fps 画面可靠）

`Gate` 加 `bool take_edge()`（poll 时置位，取走即清）；task_2 检测到 `allowed()` 翻转打一行：

```
[task2] 开火门 松开→按住（hold/evdev，第 1023 帧）
```

事后对日志/录像时序、以及"到底按没按"的争议，靠这一行裁决。

### 8.4 判据闭环（写进文档）

HUD 显示的是**代码看到的**键状态：手指按下但徽章不变 ⇒ 通道问题（跑 `keytest`，
看是不是 cvkey 兜底在扛）；徽章绿了仍不发 ⇒ 看状态行其余字段（facing / 低位靶 / 到位）。
toggle 模式程序重启后锁存归 SAFE——徽章大红底一眼可见，这是防"重启后忘解锁零发弹"的兜底。
