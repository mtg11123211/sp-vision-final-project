> 这是**副本**里的改动，原始工程 `D:\DSH\fp_aim` 一个字节都没动。

## 0. 一句话

| 新增 | 作用 | 默认 |

| **只打低位靶** | 瞄到"高"的那块板时**不许开火**，等低板转正再打 | 开（容差 0.10 m） |

这两条都**只影响"什么时候扣扳机"**，完全不影响跟踪、测距、解算。

## 2. 只打低位靶

### 2.1 为什么这么打能提高命中率

旋转靶是一台车，四块装甲板里 **1、3 号比 0、2 号高**，这个高度差就是 EKF 状态里的
`x[10] = z2 − z1`。关键在于：

- `x[10]` 是**单板观测估出来的**，而 `target.cpp` 的 `update_ypda` 在**首次换板之前
  把雅可比的后三列清零**（`H.block<4,3>(0,8).setZero()`），也就是高度差这一列在
  整个挡位里都被冻结；
- 于是**高板的 z 很可能带系统偏差** → 打高板时俯仰（pitch）会系统性偏 →
  表现就是"明明瞄了板却打在板下面/上面"；
- 低板的高度就是基准 `x[4]`，**不需要估任何东西** → 没有这个误差源。

所以"只打低位靶"= **把唯一一个系统性俯仰误差源从靶子里剔掉**，用一半的靶换零偏差。

### 2.2 规则怎么落地

```
候选板 = EKF 预测的 4 块（z = x[4] + dh，dh 见 target.cpp 的 h_armor_xyz）
z_min  = 候选板里的最低高度
低位组 = z ≤ z_min + DSH_LOW_PLATE_Z_TOL 的那些板
瞄的板不在低位组 ⇒ 不许开火（等它转走、低板转正）
```

**刻意设计：高低分不开的时候规则自动失效**（`active = false`）。
`x[10]` 一开始是 0（`x0[9] = 0`），要靠观测慢慢学；学不出来时如果硬套规则，
会把所有开火机会都误杀。所以宁可这条规则偶尔不生效，也不要误杀。

### 2.3 代价（必须知道）

- **弹频砍半**：一圈四块板，只有 0、2 两块是低位 ⇒ 一圈只打得到 2 发。
  4 rad/s 时约 **1.27 Hz**（原来 3.5 Hz），3 rad/s 时约 1.1 Hz。
  10 发额度会从 3 秒打光变成 8 秒打光——**省额度，不是省时间**。
- **只有在"高板确实偏高"时才有效**：如果车机上四块板实际等高（`x[10]≈0`），
  规则自动失效，等于没加这条。

### 2.4 怎么调

| 环境变量 | 默认 | 含义 |
|---|---|---|
| `DSH_LOW_PLATE` | 1 | 规则总开关，设 0 完全恢复原行为 |
| `DSH_LOW_PLATE_Z_TOL` | 0.10 (m) | 高度容差。**要小于真实高度差、大于 EKF 的高度噪声** |

现场标定：看日志里 `dz=` 这一列（= 瞄的板比最低板高多少）。
- `dz` 稳定在 0.00x → 高度差没学出来，规则在空转，把容差调小或先别用；
- `dz` 稳定在 0.1x 以上 → 规则在起作用（瞄到高板时 `低位靶=否`）。

## 3. 人按住 F 才允许开火

### 3.1 语义

- 程序**一直跟踪、一直解算、一直在算提前量**，只是**不扣扳机**；
- 人按住 F ⇒ 允许开火；松开 ⇒ 立刻停火（下一帧就生效）；
- 配合低位靶规则，就是"**人在认为合适的时刻按住 F，程序在那一瞬间用最准的解算打出去**"。

好处：10 发额度是稀缺资源，**把"什么时候打"的决定权交回给人**，程序只负责"打得准不准"。

### 3.2 取键的四级降级

| 优先级 | 后端 | 是不是"真按住" | 备注 |
|---|---|---|---|
| 1 | Linux evdev（`/dev/input/event*`） | ✅ 是 | 能同时拿到按下/松开；**不需要窗口有焦点** |
| 2 | Windows `GetAsyncKeyState` | ✅ 是 | 笔记本上调试用 |
| 3 | 终端 raw 模式 | ≈ 靠键盘自动重复近似 | 首次重复前有约 0.5 s 空档 |
| 4 | OpenCV 窗口按键 | ≈ 同上 | 要求窗口有焦点；**只在没有前三种时启用** |

车机一般是远程/X11 转发，**窗口没有焦点时 `cv::waitKey` 收不到键**，所以 evdev 才是主力；
启动日志里会打 `按键后端 evdev:/dev/input/event3 ...`，一眼能看出走的是哪条通道。

### 3.3 环境变量

| 环境变量 | 取值 | 含义 |
|---|---|---|
| `DSH_FIRE_KEY` | `hold`（默认） | 必须按住 F |
| | `toggle` | 按一次 F 切换许可（适合鼠标/手柄/远程） |
| | `always` | 永远允许（等于关掉这个门，回到全自动） |
| | `never` | 永远不允许（调试用） |
| `DSH_FIRE_KEY_ENABLE` | 1/0 | task_2 默认 1；**task_3 默认 0**（前哨站要 12 Hz 连打 75 发，人按不住） |
| `DSH_FIRE_KEY_DEV` | 路径 | 指定用哪个 evdev 设备 |

### 3.4 代价

- **人按住 F 的那段时间会白白消耗"挡位时间"**，但不发弹 → 不消耗额度 ✓；
- 人的反应时间（0.2~0.4 s）会**错过最佳窗口** ⇒ 弹频实际上比 1.27 Hz 更低。
  建议：**用 toggle 模式**（按一下锁住，让程序自己挑时机打），而不是死按着。

## 4. 上车顺序（照这个顺序做，别跳）

### 第 0 步：只验按键通道（不跑车、不上电控）



### 第 1 步：编译 + 跑一次，先看日志


### 第 2 步：先别打，先看三样东西

| 看什么 | 期望 | 不对怎么办 |
|---|---|---|
| `dz=` | 稳定在某个值（>0.05 说明高度差学出来了） | 一直是 0.00x → 规则空转，把 `DSH_LOW_PLATE_Z_TOL` 调小再试 |
| `低位靶=` | 在"是/否"之间来回切（跟着板转） | 一直是"是" → 四块板等高，规则没用（正常） |
| `key=` | 按住 F 变 True，松开变 False | 不变 → 按键通道没通，回第 0 步 |

### 第 3 步：打 3 发（这才是真正的验证）

- 人**按住 F**（或 toggle 模式锁住）→ 数 `rounds` 有没有涨；
- 弹着点应该集中在**低板**上，而且**每次都落在板的中间附近**；
- 记录：`shots=3 hits=?`。

### 第 4 步：与原版对比（很重要）

用同一台车、同一批靶、同一转速，原版打 3 发、副本打 3 发，比命中率。
**如果副本的命中率没有明显高于原版，说明"高板俯仰有系统偏差"这个假设不成立**，
就把 `DSH_LOW_PLATE=0` 关掉，只保留 F 键门。

## 6. 和之前几轮审核结论的关系（别忘了这几条）

这两条新策略**不解决**下面这些问题，仍然要按之前的结论处理：

| 问题 | 状态 | 处理 |
|---|---|---|
| `DSH_LEAD` 缺省 0 ⇒ 延迟补偿没开 | **仍然没解决** | 现场卡 §2：`DSH_LEAD=0.057` 起步，再用 §3 斜率法定标到 0.07~0.09 |
| 到位门限 0.8° 骑在实测 errY（0.64/1.51°）中间 | **仍然存在** | 不发弹就 `DSH_ARRIVE_DEG=1.2` 起步 |
| `target_static`(\|w\|<0.5) 会关掉"一块板一发" | **仍然存在** | 看 `rounds` 涨得比预期快就是它 |
| A→B→A 跳板洞 | **仍然存在** | 同上 |
| `max_rounds_per_stage: 0` → 10 发额度软件不拦 | **仍然存在** | 人盯 `rounds` |
| 官方初始代码的 8 个框架文件改动（能否提交） | **仍然要问教练** | 与本次改动无关，但优先级更高 |

**低位靶规则和 F 键门都是"减少浪费"型的，不是"提高精度"型的**：
它们让你在有限的 10 发里，只在对的时刻、对的靶子上扣扳机。
真正的精度还是要靠 `DSH_LEAD`（延迟补偿）和到位门限（云台跟得上）。
