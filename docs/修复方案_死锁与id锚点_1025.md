## 一、问题一：NIS 永久拒收导致滤波器死锁

### 1.1 现场表现

- 画面里有绿框、`tgt YES`，但 `rounds` 一直是 0；
- HUD 上 `z4`、`w`、`arr`、`aim_id` 全部冻结，几秒内一个数字都不动；
- 不报错、不退出，`nis_failure_rate` 显示 0（看起来"很健康"）；
- `arr` 停在 90° 上下，永远过不了 `DSH_T3_ARRIVE_DEG` 门；
- **重启进程后立刻恢复**（`z4` 回到 1.11–1.17 正常区间）。

录屏证据：`20261025-0605-07`（`z4=0.642` 恒定）、`20261025-0608-39`（重启后 `z4=1.117`，正常出弹）。

### 1.2 根因链

| 步骤 | 位置 | 说明 |
|---|---|---|
| ① 单帧先验 | `tasks/auto_aim/target.cpp:74` `center_z = xyz[2]`、`:82` `x0{..., center_z, 0, ypr[0], ...}` | 滤波器初值完全取自**第一帧**的 PnP。那一帧斜视/半遮挡 ⇒ `z` 偏 0.5 m、`ypr` 偏几十度。 |
| ② 全量回滚 | `target.cpp:318-320` `ekf_.x = x_before; ekf_.P = P_before;` | NIS 超阈把状态**和协方差**一起回滚 ⇒ 滤波器一次都没机会收敛，等于原地不动。 |
| ③ 失败信号被抹掉 | `target.cpp:325-333` `recent.pop_back();` | 为避免 `nis_failure_rate` 顶到 1.0 误伤 `stable`，拒收后把失败标记退掉 ⇒ **连续拒收在系统里没有任何计数器**，外部看不到异常。 |
| ④ 无出口 | `src/task_3.cpp:261` `if (!target.update_checked(...))` | 只判断单帧是否被拒，从不重建目标。唯一恢复手段是重启进程。 |

② 与 ③ 形成一个自锁环：状态不动 ⇒ 预测角不跟转动 ⇒ 残差持续超阈 ⇒ 继续拒收。`w` 永远是初值 0（`x0` 第 8 分量），板以 143°/s 转，误差单调变大，**几何上不可能自己恢复**。

### 1.3 修法（三处，按优先级）

**A. 必须有：连续拒收看门狗**

```cpp
// tasks/auto_aim/target.hpp（新增成员）
int consecutive_rejects_ = 0;
bool needs_reinit() const { return consecutive_rejects_ >= 20; }  // 20 帧 ≈ 0.35 s

// tasks/auto_aim/target.cpp :update_checked()
if (ekf_.last_nis > nis_reject_threshold) {
  ++consecutive_rejects_;
  // ...原有回滚逻辑...
  return false;
}
consecutive_rejects_ = 0;   // 只要有一帧被接受就清零
return true;

// src/task_3.cpp，update 调用处之后
if (target.needs_reinit()) {
  tools::logger()->warn("[task3] 连续 NIS 拒收 20 帧，丢弃目标重建");
  target_ready = false;      // 走原有的"无目标"分支，下一帧用新观测重建
  last_seen = now - std::chrono::milliseconds(target_hold_ms + 1);
}
```

重建路径已存在（丢目标超过 `target_hold_ms` 会重新 `emplace`），不需要新写。

**B. 建议：拒收时只回滚 x，不回滚 P（或把 P 放大 10 倍）**

让滤波器保留"我不确定"的信息，下一帧就有更大的接受窗口，而不是被钉死在一个错误先验上。

```cpp
ekf_.x = x_before;
ekf_.P = P_before * 10.0;   // 而不是 P_before
```

**C. 加固：先验合理性钳位**

前哨站三块板的世界高度合理区间约 0.8–1.6 m。构造时若 `center_z` 落在外，直接拒绝建目标、等下一帧。

### 1.4 验收标准

| 项目 | 通过判据 |
|---|---|
| 死锁不再持续 | 人为制造坏初值（遮挡首帧）后，程序在 1 s 内自动恢复出弹，无需重启 |
| 日志可观测 | 出现 `连续 NIS 拒收 N 帧，丢弃目标重建` 告警 |
| 正常场无副作用 | 与冻结版并排跑 30 s，发数差异 < 5% |

## 二、问题二：id 每次重启重排，id=1 永远对不上真实高度

### 2.1 现场表现

- 每次重启（或丢目标重建）后，三块板对应的 `aim_id` 会重新排列；
- 某一层始终打不准，且换层后偏差方向跟着变；
- 用 `DSH_DZ0/1/2` 逐层补偿后，重启一次可能又错。

### 2.2 根因

`tasks/auto_aim/target.cpp:82`：

```cpp
Eigen::VectorXd x0{{..., ypr[0], 0, r, 0, 0}};
//                        ↑ x[6]，即 id=0 的相位 = 第一眼看到的那块板
```

三块板的位置全部由它派生（`target.cpp:285 / 407`）：`angle = x[6] + id·120°`。

**id 是"相对第一眼的编号"，不是物理身份。** 而高度又按 id 给（`target.cpp:418-419`）：

```cpp
if (id == 1) dh = x[9];
else if (id == 2) dh = x[9] + x[10];
```

`x[9]`、`x[10]` 在 `update_ypda` 里被冻结（`target.cpp:264`），是常数 0.1。所以编号只要循环移位一格，三层高度就整体错位一格：

| 第一眼看到 | id0 | id1 | id2 | 结果 |
|---|---|---|---|---|
| 底板 | 0 ✔ | +0.1 ✔ | +0.2 ✔ | 全对 |
| 中板 | 0 ✘ | +0.1 ✔ | +0.2 ✘ | id0/id2 错 |
| 顶板 | 0 ✘ | +0.1 ✘ | +0.2 ✔ | id1 必错 |

"id=1 永远对不上"就是第三行：id1 恒为 +0.1 m，而它可能是底板（实际 0）或顶板（实际 +0.2），误差正好一格 ≈ 0.1 m ≈ 1.2°，等于一块板高。

### 2.3 修法

**A. 瞄准高度改用实测板高（首选，3 行）**

`src/task_3.cpp:316` 附近：

```cpp
const double dz_trim = (aim_id == 0) ? dz0 : ((aim_id == 1) ? dz1 : dz2);
// 三块板绕竖直轴转动，z 不随转动变化 ⇒ 当帧量测的 z 就是弹着瞬间的高度
if (chosen != nullptr) {
  plate[2] = chosen->xyz_in_world[2] + dz_trim;
} else {
  plate[2] += dz_trim;
}
```

量测数据本来就在手边——`src/task_3.cpp:199/204/228` 已经用 `xyz_in_world[2]` 做顶部板筛选，只是没把它用在瞄准上。

**注意**：切换后 `DSH_DZ0/1/2` 必须归零重标（现值 0.040/0.200/0.150 是"补偿 id 错位"标出来的，实测高度已经把这一项算进去了）。

**B. 彻底版：初始化收敛后按实测 z 排序重排 id**

跑满一圈、三块板的高度都被量到之后，按实测 z 从小到大重新定义 id0/1/2，使"id 与层高一一对应"。实现上是在 `update_ypda` 之后加一次性的重排，代价是要处理已收敛的状态转移，风险高于 A。

**C. 不推荐：放开 dh 让滤波器自己学**

`x[9]`/`x[10]` 现在是冻结的，放开会让三个高度与角度强耦合，观测只有 4 维，容易发散。

### 2.4 验收标准

| 项目 | 通过判据 |
|---|---|
| 重启不变 | 连续重启 5 次，同一层的 `z − z4` 读数一致（±5 mm） |
| 三层一致 | 三块板弹着都落在中心 ±30 mm，不需要按重启次数改参数 |
| 无副作用 | `z` 的抖动（量测噪声）不引起云台抖动：对比开/关该修法的 `pitch` 波形 |

## 三、实施顺序与回退

1. **先做 2.3A**（一行，风险最低），跑一场验证三层。
2. **再做 1.3A**（看门狗），用"遮挡首帧"的办法人为触发死锁验证恢复。
3. 1.3B/1.3C 作为加固随后跟进。
4. 回退方式：所有改动都在 `src/task_3.cpp` 与 `tasks/auto_aim/target.{hpp,cpp}` 三个文件内，回退即 `git checkout` 到 `task3` 分支的上一提交；冻结参数（到达门控 25°、dz 三档、relax=1）在代码缺省里，不受影响。

## 四、面试可讲的三句话

1. **编号不是身份**：id 从第一帧相位推出来，三块板 120° 对称、锚点任意，所以重启必然重排；一旦把高度绑在 id 上，就变成系统性错位。
2. **拒收必须有出口**：全量回滚 + 抹掉失败标记，等于把滤波器锁死在错误先验里，而且没有任何信号暴露它——表现为"一切正常但就是不开火"。
3. **先验必须可证伪**：单帧 PnP 直接当先验、没有任何合理性检查，现场一次坏帧就能锁死一整场。
