## 一、硬错 3 条：会让现场判断失效

### H1　§2 P0 的通过判据引用了一行**代码里根本不存在**的日志

文档写：「出现 `[task2] 到位门控`、**`[task2] 开火闸`** 两行」。

实测（`grep -c '开火闸' src/task_2.cpp` = **0**）。代码里 `[task2]` 前缀的启动日志只有两行：

```
[task2] offset yaw=0.00(yaml) pitch=0.00(yaml)  源: yaml 值 0.00/0.00
[task2] 到位门控 = 开（yaw 0.80° / pitch 1.28°，连续 3 帧）｜看门狗 关｜板面正对 ±25°、摆出 35° 才重新上膛（一块板只打一发）｜发弹间隔 0.20 s
```

⇒ **P0 永远判不通过**，现场会误判"启动失败"。

**改法**：判据改成 `[task2] offset` + `[task2] 到位门控` 两行（这两行确实每次启动都打，且能同时确认 offset 是 0）。

### H2　§1.3 `grep -c 'DSH_LEAD'` 的期望值写错

| grep | 文档写的 | 实测 | 结论 |
|---|---|---|---|
| `plate_facing_deg` | >= 3 | **4** | 能过（可收紧成 `== 4`） |
| `target_static` | 2 | **2** | ✓ |
| `DSH_LEAD` | 2 | **3** | ✗ **现场看到 3 会以为"多了/不对"** |

`DSH_LEAD` 的三处在 `:435`（注释）、`:436`（getenv）、`:440`（注释）。

**改法**：`grep -c 'DSH_LEAD' src/task_2.cpp  # 期望 >= 3`。

### H3　§1.3 的 yaml 验收 grep 会多匹配两行注释

`grep -n 'yaw_offset\|pitch_offset' configs/standard.yaml` 会命中 **19、24（都是注释）、25、26** 共 4 行，
而判据写"两个都必须是 0.0" ⇒ 现场容易把注释行当成配置值。

**改法**：`grep -nE '^(yaw_offset|pitch_offset):' configs/standard.yaml   # 应恰好 25、26 两行，都是 0.0`

## 二、数字与依据要改 4 条

### N1　§7「4 块板一圈 4 发，实际 3.5 Hz」——3.5 Hz 是**上限**，平均是 **2.55 Hz**

```
4 rad/s ⇒ 一圈 2π/4 = 1.571 s；4 块板每圈各 1 发 ⇒ 4 / 1.571 = 2.55 Hz
3.5 Hz 只在「上一发打在窗口末尾(facing=+25°)、下一发打在窗口开头(facing=−25°)」这种极限情况出现。
```
⇒ §7 该写「**平均 2.55 Hz（最快 3.5 Hz）**」。
⇒ 补一条（副本里新增的"只打低位靶"策略生效时）：**每圈只打 2 块低板 ⇒ 1.27 Hz**。

### N2　§5 把"每帧 0.25°"判为错误——这是把两个量混了

| 量 | 值 | 决定什么 |
|---|---|---|
| 靶柱**转过的相位** | 229°/s ÷ 58 fps = **3.9°/帧** | facing 变化多快、板多久出 ±25° 窗口 |
| 板在**画面里的视在位移** | 14.55°/s ÷ 58 fps = **0.25°/帧** | **指令角每帧动多少** = 到位门限实际卡的那个量 |

到位门限比的是 `aim_yaw` vs 云台反馈，`aim_yaw` 跟的是**板的视在位置** ⇒ 门限估算该用 **0.25°/帧**。
文档 §5 说的后果"按 0.25° 估误差 → 把门限放大 15 倍"不成立：门限 0.8° 比的是**绝对角差**，不是每帧增量。

**但 §5 的结论我同意**：这三条不用追——现场的主要矛盾是"打不出去"和"偏几个靶宽"。

### N3　§3 D-4 的 lead 符号判据建议再加一条"看画面"

`8.29°` 这个数复核**正确**（0.57 s × 14.55°/s）；"w>0 时后者变小"来自 C2 的推导（w>0 ⇒ 板往画面右走 ⇒ 视在 yaw 变小）。
但这条**依赖世界系 +Y 朝左的约定**，最可靠的判据是画面：

> `DSH_LEAD=0.57` 那场，准星应明显**领先**板子（偏向板子转过去的方向）；若落在板子另一侧 ⇒ 符号反。

建议两条都做：数字比 + 肉眼看。

### N4　§3 D-1「窗口正常会在 0.1~0.15 s 内打开」偏乐观

窗口 50°，4 rad/s 下 = 50/229 = **0.218 s** ⇒ 改成 0.2 s。
