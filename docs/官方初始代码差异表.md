## 2. 11 个框架文件，逐个说明（申报用）

| 文件 | 改了什么 | 为什么必须改 | 能不能挪进 `src/` |
|---|---|---|---|
| `io/gimbal/gimbal.cpp` | ① 发送前 `pitch` 取反 ② `send()` 加 target 字段 ③ 录包/回放状态源 ④ 断线重连 | ① **现场实测**"板子上移、云台下移"，不取反俯仰全反；② 原来每帧都上报"英雄"；③④ 是工具链 | ① 能（src 里取反再 send）；② **不能**（协议字段）；③④ 能（挪到 src） |
| `io/gimbal/gimbal.hpp` | 加 `send()` 第 5 参、`replay()`、回放状态成员 | 同上 | 同上 |
| `io/camera.cpp/.hpp` | 暴露 `dev_ts()`（相机硬件时间戳）+ 录包/回放钩子 | 延迟探针要"曝光时刻"，离线复现要录像 | 能（但 `dev_ts()` 要相机驱动支持） |
| `io/hikrobot/hikrobot.cpp/.hpp` | 把 `dev_ts` 透出来 | 同上 | 能（但要动驱动封装） |
| `tasks/auto_aim/armor.cpp/.hpp` | 颜色映射 `0=红 / 1=蓝` + `priority` 给初值 | 实车模型与训练时类别顺序相反；`priority` 原来未初始化就被读 | **能**：用 `armor.class_id` 在 src 里判颜色即可，不必改 armor.cpp |
| `tasks/auto_aim/target.cpp/.hpp` | ① 官方 10-19 修复（`h_armor_xyz` 高度）② 前哨站阶梯分层 ③ NIS 拒收+回滚 ④ 发散判据 ⑤ P0/过程噪声 TODO | ① 官方原样就修不了 1/3 号板的高度；②③④⑤ 是官方留的 Task_2/Task_3 TODO | ②⑤ 官方 TODO 本来就在这里填，**合理**；③ 可挪到 src（自己维护 NIS 窗口） |
| `tasks/auto_aim/yolos/yolov5.cpp` | 颜色映射 + ROI 坐标还原 | 官方 ROI 关闭；我们开了 800×800，必须把裁剪坐标加回去 | 能 |
| `tools/extended_kalman_filter.cpp/.hpp` | NIS/NEES 阈值 `1.5` → `9.488 / 19.68` | **官方 1.5 是错的**：观测量 4 维，NIS 服从 χ²(4) 均值就是 4，阈值 1.5 会把 83% 的正常帧记成"失败"；任何用 `recent_nis_failures` 做开火条件的实现会**永不开火** | 能（在 src 里自己算失败率） |

**结论**：
- **必须留在框架里的只有 3 处**：① `gimbal.send` 的 target 字段（协议）、② `camera.dev_ts()`（驱动暴露）、③ `armor` 的颜色映射（若不愿改，可用 `class_id` 替代）。
- 其余 8 处都可以下沉到 `src/`，代价是重写一小段。
- **要问教练的一句话**：「作业是否允许修改 `tasks/auto_aim/`、`tools/`、`io/` 这些框架目录？如果不允许，我把上面 8 处下沉到 `src/` 重新交一版。」
