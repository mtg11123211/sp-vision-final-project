**判读**：
- k 实测 ≪ k 理论 ⇒ 靶子没在转 / ω 不对 / 落点读反了 ⇒ **别用这个结果**；
- 新 T 落在 0.02~0.20 s 之外 ⇒ 复核读数与 ω；
- **M4 必须在 M1（零位）之后做**，否则 T 会把零位误差吸收进去。

## 五、顺序约束（别打乱，理由见《现场测量清单.md》§4）

```text
M1 零位 ─► M2 errY/延迟/几何 ─► M3 符号 ─► M4 总提前量 T    # 先标定：没零位 ⇒ 门限没有依据
M5 门限 ─► M6 基线 ─► M7 低位 ─► M8 arrival ─► M9 人工门  # 每场只改一个变量
```

| 违反 | 后果 |
|---|---|
| M1 没做就 M4 | lead 把零位误差吸收 ⇒ 以后改零位，lead 就错了 |
| M2 在静止靶上做 | 测不出跟踪滞后 ⇒ 门限没依据 |
| M3 在 M4 之后 | 符号反 ⇒ 斜率外插出垃圾值，还可能误删 `+ M_PI` |
| M4 两场转速/距离不一致 | k 无效 |
| M6 在 M1/M3/M4/M5 之前 | 对照组本身有偏 ⇒ 后面每场都比错 |
| M7/M8 一次改两个 | 分不清是谁带来的变化 |
| 延迟测量时开录像 | 写盘抖动污染 `send_ns` ⇒ B1/B2 偏大 ⇒ lead 标错 |

## 六、每轮只改一个变量的顺序

```text
① 挡位确认 AUTO_AIM（M0）                    # 挡位不对，后面全白测
② 零位（M1）→ yaml                          # 没零位别测 errY
③ 门限（M2 的 errY → M5）                   # 抄 M2 的最大 ×1.2~1.5
④ 总提前量（M3 → M4）                       # 斜率法，两场一组
⑤ 低位靶 warmup（M7）                        # DSH_LOW_PLATE=1
⑥ 到达时刻选板（M8）                         # DSH_AIM_SELECT=arrival
⑦ 人工开火门（M9）                           # 正式提交那几挡开着，每挡 ≤10 发
```

**每改一个变量**，按这三行走：

```bash
~/run_measure.sh preflight               # 每改一个变量后先跑：启动日志里的参数必须是新的
DSH_LEAD=0.080 ~/run_measure.sh spin p7  # 跑一场（子命令见清单对应 M 步，DSH_* 照常透传）
cat logs/summary_*.txt                   # 退出后，把这一场 A/B/C 抄进上面的总表
```
