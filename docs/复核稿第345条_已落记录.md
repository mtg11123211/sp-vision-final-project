## 第 4 条：静止靶判定（已落，**实现与复核稿建议不同**）

复核稿建议：用 `|x[7]| < 0.15` + 连续 10 帧。

**我改成量「当前瞄的这块板，这一帧的朝向变了多少度」**：

```cpp
      //   这样判据不依赖 w 的符号和收敛过程，w 反向过零也不受影响。
      // 注意 facing_deg 是**度**，不能拿 tools::limit_rad 去包（它是按弧度写的 2π 环绕），
      // 这里自己按 ±180° 环绕。
      double d_facing_deg = facing_deg - last_facing_deg;
      while (d_facing_deg > 180.0) d_facing_deg -= 360.0;
      while (d_facing_deg < -180.0) d_facing_deg += 360.0;
      d_facing_deg = std::abs(d_facing_deg);
      last_facing_deg = facing_deg;
      facing_still_frames = (d_facing_deg < 0.5) ? facing_still_frames + 1 : 0;
      const bool target_static = facing_still_frames >= 10;  // 连续 10 帧 ≈ 0.17 s
      plate_armed = target_static || (aim_id != last_fired_plate) ||
                    (std::abs(facing_deg) > plate_rearm_deg);
```

**为什么不照复核稿的写法**：
| | `|x[7]| < 0.15` | **量 facing 的逐帧变化** |
|---|---|---|
| 依赖 EKF 的 w | 是 | 否 |
| 起步爬升期 | w 还没收敛出来 ⇒ 仍会误判成"静止" ⇒ 规则失效 | 每帧 facing 变 3.9~11.7° ⇒ 计数器每帧清零 |
| w 反向过零 | `|w|` 掉到 0 ⇒ 误判成"静止" | facing 仍在快速变化 ⇒ 不会误判 |
| 静止靶 | w≈0 ⇒ 判定正确 | 每帧只变 0.03°（量测噪声）⇒ 判定正确 |
| 换板瞬间 | — | facing 跳变 ⇒ 计数器清零（保守，正确） |

阈值 0.5°/帧 对应 0.5 rad/s 的转速；赛规要求 3~9 rad/s，**远离这个边界**。

**顺带修的两个 bug**（原来就有）：
1. `facing_deg` 是**度**，而 `tools::limit_rad` 是按**弧度**写 2π 环绕的 ——
   直接拿它包度值会把 3.9° 算成 136°。所以这里自己按 ±180° 环绕。
2. 换目标 / 滤波器重建时，`last_fired_plate` 没有清零 ⇒ 新目标的 0 号板会被当成
   "刚打过的那块"而挡掉。现在重建时一起清 `aim_id_persist` / `last_fired_plate` /
   `facing_still_frames`。

**副作用**：真·静止靶（零位标定用的那种）现在要**连续 0.17 s** 才被认出来 ⇒
标定时建议加 `DSH_PLATE_REARM_DEG=0.01` 显式放开。

## 第 5 条：`aim_id` 跨帧保持（已落）

```cpp
  // 上一帧真正选中的板（跨帧记忆）。
  // 原来 aim_id 每帧都被重置成 target.last_id ⇒ 「5° 迟滞」的比较基准永远是 last_id、
  // 不跨帧 ⇒ 两块板 facing 相差 ±5° 的窄带里，选板会跟着 last_id 闪。
  int aim_id_persist = -1;
```

```cpp
      const auto xyza_list = target.armor_xyza_list();
      // aim_id 跨帧保持：比较基准变成「上一帧真正选中的那块」，5° 迟滞这才成立。
      // 还没选过、或者上一帧那块已经越界（换目标/板数变了）⇒ 退回 EKF 的关联结果。
      int aim_id = aim_id_persist;
      if (aim_id < 0 || aim_id >= static_cast<int>(xyza_list.size())) {
        aim_id = (target.last_id >= 0 && target.last_id < static_cast<int>(xyza_list.size()))
                   ? target.last_id
                   : 0;
      }
      // …（argmin 选板，5° 迟滞的比较基准就是上面这个 aim_id）…
      aim_id_persist = aim_id;  // 跨帧记忆，供下一帧做 5° 迟滞比较
```

**清零时机**：换目标（`target.name != armor.name`）与滤波器重建（`diverged()`）时，
`aim_id_persist` / `last_fired_plate` / `facing_still_frames` 一起清零。

**判据**：`grep '选板变化' logs/*.log | wc -l`
- 正常一次跑下来，选板变化条数应 ≈ 转速 × 圈数（每 90° 相位换一次板），
  4 rad/s 下一圈 1.57 s ⇒ 约 2.5 次/秒；
- 若出现几十条/秒的抖动 ⇒ 迟滞还有问题（或者 `aim_id` 被别处重置了）。
