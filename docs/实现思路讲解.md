## 0. 总览：一条决策链，三层

副本的开火决策最终是**三个"与"**（`task_2.cpp:767-770`）：

```cpp
const bool would_fire = has_detection && stable && interval_ok && rounds_ok
                      && mode_ok && !holding && plate_ok && key_ok;   // ← key_ok 是新增
const bool fire = would_fire && arrive_ok && !latency.step_enabled();
```

把它拆成三层，后面每个机制都落在其中一层：

| 层 | 回答的问题 | 本副本里的机制 |
|---|---|---|
| **① 几何/感知层** | 瞄的是**哪块板**、**什么时候正对** | 到达时刻选板（`task_2.cpp:527-572`）、面朝门控 `facing_ok`（`:572`） |
| **② 策略层** | **这一枪值不值得打** | 低位靶规则（`:537-541`）、一块板一发（`:520-529`）、到位门控 `arrive_ok`（`:645`）、命令突变保护（`:619-622`） |
| **③ 授权层** | **允不允许打** | 人工开火门 `key_ok`（`:599`）、电控挡位 `mode_ok`（`:593`） |

设计原则：**每层都只用环境变量开关**，且**默认值＝"不做这条策略"或"这条策略无害"**：

| 层 | 默认 | 为什么默认是它 |
|---|---|---|
| 几何层（到达时刻选板 / 出弹延时） | 全关（`current` / 0 s） | 会改变弹道指向，必须 A/B 后再开 |
| 策略层（低位靶 / 线性容限） | 低位靶 = **warmup**（平靶自动失效、收敛后自动放开，趋近无害）；线性容限 = 关（保持原角度门限） | 不改变"打哪块板"的语义，只在"高板 z 还没学准"时拦一下 |
| 授权层（人工开火门） | **关**（`DSH_FIRE_KEY_ENABLE=0`） | 正式提交每任务只有一次机会，操作员忘按 F = 整场零发；调试期显式开，HUD 徽章一直显示状态 |

这样每条新策略都能在车上单独 A/B，出问题能立刻定位到层。

## 1. 机制一：只打低位靶，不打高位靶

### 1.1 为什么这么做（可推导，不是玄学）

车体四块板里 **1、3 号比 0、2 号高**，这个高度差就是 EKF 状态里的 `x[10] = z2 − z1`。
**口径（2026-10-21 评审修正，别再说"永久冻结"）**：`target.cpp` 的 `update_ypda` 只在
**首次换板前**把雅可比后三列清零（`H.block<4,3>(0,8).setZero()`），**换板之后是允许单板观测更新高度差的**。
所以真实情况是**弱化版**：**x[10] 从 0 起步、先验很紧（P0=0.001）、靠换板观测慢慢收敛，
收敛之前高板的 z 偏低**（不是"永久冻结"）。
⇒ 打高板时俯仰可能系统性偏 ⇒ 现场表现就是"明明瞄了却打在板下面"；
⇒ 但这是**瞬态**问题，收敛后就没了 ⇒ 所以规则做成**三态**（§1.2/§1.4），暖机期只打低位、收敛后自动放开。

低板的高度就是基准 `x[4]`，**不需要估任何东西** ⇒ 零误差源。
所以"只打低位靶"= **把唯一一个系统性俯仰误差源从靶子里剔掉**，代价是机会减半。

### 1.3 状态机（三态 + 两个防抖）

```
DSH_LOW_PLATE = 0/off    → 完全不参与（连几何都不算）
              = 1/warmup →【默认】不可信时只打低位；可信后自动放开高板
              = 2/always → 永远只打低位（保守模式）

几何：z_spread = z_max − z_min  ← 这就是 x[10]（瞄高板时等于 z_aim − z_min）
① active 迟滞（★2）：进入 spread > z_tol；退出 spread < 0.5·z_tol
   ⇒ 差值在容差边界抖动时不会让 active 反复开关、高板被瞬时放行
② 信任计时（★3）：只在「有观测 && active」的帧上累计，连续 DSH_LOW_PLATE_TRUST_S 秒 ⇒ trusted
   ⇒ 没观测就重新计时，不拿旧数据判收敛
③ 重建作废：换目标 / 滤波器重建 ⇒ generation++ ⇒ 信任清零（高度差重新从 0 学起）
```

**`active == false` 时规则自动失效**（四板同高 ⇒ spread 永远 < tol ⇒ warmup 与 always 等价，安全）。
`task_2.cpp:467 / 493` 的 `++target_generation` 是"重建"的唯一入口 ⇒ 不会漏判废。

### 1.4 开关与判据

| 变量 | 默认 | 说明 |
|---|---|---|
| `DSH_LOW_PLATE` | `1`（warmup） | 0/off 不参与｜1/warmup 不可信时只打低位、可信后放开｜2/always 永远只打低位 |
| `DSH_LOW_PLATE_Z_TOL` | 0.10 m | **要小于真实高度差、大于 EKF 的高度噪声** |
| `DSH_LOW_PLATE_TRUST_S` | 4.0 s | 高度差稳定多久算收敛 |

判据看日志 `fire-gate` 行里的 `low=(dz=… 低N共M块)` 与 HUD 的 `plate=LOW/HIGH … trust=x/y s`：
- `dz`（= z_spread）长期 ≈ 0.00x ⇒ 高度差没学出来，规则在**空转**（不是坏事，但要知道自己没在用这条策略）；
- `dz` > 0.1x 且 `plate=HIGH` ⇒ 规则在拦（瞄的是高板），正常，等低板转正；
- 信任计时走满 ⇒ 打一行"x[10] 视为已收敛，放开高板"，之后机会恢复到 2.55 Hz。

**代价**：warmup 模式下**暖机约 4 s**（信任计时）内只打低位，之后恢复 2.55 Hz；
`always` 模式则**一直**只有 1.27 Hz。

## 2. 机制二：人按住 F 才允许开火

### 2.1 语义

程序**一直跟踪、一直解算、一直在算提前量**，只是**不扣扳机**；
人按住 F ⇒ 允许开火，松开 ⇒ 下一帧就停。
配合低位靶规则 = "**人在认为合适的时刻按住 F，程序在那一瞬间用最准的解算打出去**"。
作用是把 10 发这种稀缺额度花在对的时刻（官方框架里对应 yaml 的 `auto_fire: false`，是同源的正当做法）。

## 3. 机制三：复核稿第 3/4/5 条

### 3.1 选板跨帧保持（真迟滞）

**问题**：原来 `aim_id` 每帧都被重置成 `target.last_id`（`:398` 附近的旧写法），

### 3.2 静止靶判定：量"朝向的逐帧变化"，不看 `x[7]`

**问题**：`target_static = |x[7]| < 0.5` 一旦成立，`plate_armed` 恒为真 ⇒
"一块板只打一发"这条规则**整个失效** ⇒ 5 Hz 对着同一块板连打 ⇒ 纯哑炮、白吃 10 发额度。
而 `x[7]` 在**起步爬升**和**w 反向过零**时都会掉到很小 ⇒ 正好是误判场景。

**做法**：直接量"当前瞄的这块板，这一帧的朝向变了多少度"。

| 位置 | 作用 |
|---|---|
| `src/task_2.cpp:337-338` | `last_facing_deg` / `facing_still_frames` 跨帧状态 |
| `src/task_2.cpp:341 / 377` | `frame_dt_s`：真实帧间隔（阈值要按 °/s 给，★7） |
| `src/task_2.cpp:600-608` | 逐帧差分（**自己按 ±180° 环绕，不能用 `tools::limit_rad`，它是按弧度写的**）+ 换算成 °/s |
| `src/task_2.cpp:609` | `target_static = facing_still_frames >= static_frames_needed` |
| `src/task_2.cpp:610-612` | 并进 `plate_armed`（与"换板"或"摆出 35°"并列） |

| 变量 | 默认 | 说明 |
|---|---|---|
| `DSH_STATIC_RATE_DPS` | 30 °/s | 角速度阈值（**帧率无关**：60 fps 下 0.5°/帧、45 fps 下 0.39 rad/s） |
| `DSH_STATIC_FRAMES` | 10 | 连续帧数（**clamp ≥1**，★6：设 0 会变成"永判静止"⇒ 一块板连打） |

**收益的准确说法（评审更正）**：不是"改善了起步爬升 / w 反向过零"——
0.5°/帧 @60 fps ≈ 0.52 rad/s，与原 `|x[7]| < 0.5` 的边界几乎重合，**这两种写法在那个场景里行为相同**。
真正的收益是：**不依赖 EKF 的 `w` 的收敛过程与瞬时噪声**，判据是直接可观测量。
代价也只是"静止开始后的第一发有 0.17 s 识别延迟"，且与 `min_frames_for_fire` 的暖机并行，实际几乎无感。

## 4. 机制四：官方 sp_vision_25 的三条（默认全关）

### 4.1 到达时刻选板（官方 `aimer.cpp:61,84-116`）

官方是 `predict(future + fly_time)` → `choose_aim_point(预测后的 target)`，迭代 10 次收敛。
**你是"现在正对就选板"** ⇒ 4 rad/s、飞行 126 ms 时靶子转过 **29°** ⇒
"现在正对"的那块到弹着时已经转走 29°，真正该打的是隔壁那块 ⇒ **现在正对 ≠ 命中时正对**。

| 位置 | 作用 |
|---|---|
| `src/task_2.cpp:182-186` | `DSH_AIM_SELECT`（默认 `current`） |
| `src/task_2.cpp:527-533` | `facing_of()`：现在的朝向 = 外法线(a+π) − 中心指向相机的方向 |
| `src/task_2.cpp:535-545` | 粗估到达时间 `t_arrive = 距离/弹速 + 出弹延时`；`face_offset_deg = w·t_arrive` |
| `src/task_2.cpp:547-549` | `facing_sel()`：到达时的朝向 = 现在的朝向 + 偏移 |
| `src/task_2.cpp:550-567` | 选板用 `facing_sel`（`argmin |到达朝向|`，5° 迟滞） |
| `src/task_2.cpp:571-572` | 面朝门控也用**到达朝向**判 |

推导依据：板的外法线跟着靶子以 `w` 转 ⇒ `facing` 也以 `w` 变化 ⇒ 到达时朝向 = 现在的朝向 + `w·t_arrive`。
`w>0` 时选中的板现在的朝向应为**负**（正在转正）——这正是官方注释说的
"一侧的装甲板不断出现，另一侧不断消失，显然前者被打中的概率更高"。

### 4.3 到位容限按线性距离 + 命令突变保护（官方 `shooter.cpp:19-41`、`configs/standard3.yaml:49-52`）

官方 `first_tolerance 3°(<2m) / second_tolerance 2°(>2m)` ⇒ 换算成米 **3°×2m ≈ 105mm、2°×3m ≈ 105mm**
⇒ **恒定 ~105 mm 的线性容差**。你固定 `0.8°` ⇒ 3.15 m 处只有 **44 mm**，比官方严 2.4 倍
⇒ 这就是"门限永远打不开、`blocked` 一直涨"最可能的原因；而且**门限直接加进开火瞬间的瞄准误差** ⇒
放宽到 1.5° 就超过板半宽 1.29°，等于放注定打不中的弹出去。

### 7.1 三段预测时域（方案①：**一个旋钮**）

| 时段 | 谁补 | 参数 | 说明 |
|---|---|---|---|
| 出膛→**弹着**（飞行） | **calc_aim 内部自动** | — | 按弹道迭代出的 `t_flight`（3.15 m/25 m/s = 126 ms） |
| 曝光→**算出瞄点** + **云台跟随滞后** + **摩擦轮出弹** | **`DSH_LEAD`（总提前量）** | 0.05~0.10 s | **唯一的功能旋钮**（2026-10-21 起） |
| 其中"摩擦轮出弹"占了多少 | `DSH_FIRE_DELAY` | 现场量 | **只作记录/拆分标注，不再单独累加** |

**为什么合并成一个旋钮**：`DSH_LEAD` 修的是"炮管指旧了"（纯角度平移），`DSH_FIRE_DELAY` 修的是
"靶子真转了"（绕中心旋转）——两者**数值形式相同**（都是"视在角速度 × 时间"），二阶差 ≈ 0.1°。
分开填而实际填的是同一段延迟 ⇒ **补过头 0.83°，还会让人误判成"符号反了"**。
⇒ 方案①从**结构上**杜绝了重复补偿；`DSH_FIRE_DELAY` 非 0 而 `DSH_LEAD=0` 时启动日志会打 ⚠ 警告。
⇒ **`DSH_LEAD` / `DSH_FIRE_DELAY` 都是 `static` 一次性读取 ⇒ 改完必须重启进程。**
